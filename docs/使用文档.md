# Device Studio 使用文档

用 Studio 给设备做界面：写页面 → PC 上预览调试 → 打包 → 生成代码装进设备。

界面用普通的 HTML / CSS / JS 写——**会做网页就能上手，不需要装 Flutter、Python 或任何
开发环境**，装好 Studio 就能开工。

---

# 1. 安装与启动

- **安装包**：双击 `Myhome-x86_64-<版本>-Installer.exe`（形如
  `Myhome-x86_64-1.0.0+1-Installer.exe`）安装，装完从开始菜单或桌面启动。
  系统要求 Windows 10/11（预览用系统自带的 WebView2，无需另装）。
- **绿色版**：把整个发布目录拷到目标机器，双击 `myhome.exe` 就能用，无需安装。
- **安装目录下的 `samples\`**：随附的设备端源码与示例工程，移植时要拷进设备 SDK（见 §7）。
- 新建的设备默认放在安装目录的 `workspace/` 下，新建时也可以选其它位置。
  设备目录就是普通文件夹——**拷贝、备份、进 Git 都行**。

# 2. 界面一览

四栏布局：

```text
┌───────────┬──────────┬─────────────────────────────┬──────────────┐
│ 设备列表   │ 文件树    │ 预览 / 源码编辑              │ Inspector    │
│ ● Smart   │ ui/      │ (预览 = WebView 渲染的真实页面)│ 状态 / 命令   │
│   Light   │  index…  │                             │ 故障注入      │
│           │  css/    ├─────────────────────────────┤              │
│           │          │ Protocol Console (协议收发日志)│              │
└───────────┴──────────┴─────────────────────────────┴──────────────┘
```

菜单：

- **文件**：新建设备 / 打开设备目录 / 断开设备 / 退出
- **编辑 · 选择 · 转到**：标签页切换、复制文件路径、打开文件所在目录、重载 UI 预览
- **查看**：字体缩放、拆分预览（源码和预览同屏）、显示 Protocol Console、日志等级
- **运行**：生成代码 / 重置设备 / 断开 / UI Hot Reload
- **设置**：偏好设置…（打包时压缩图片，默认开，见 §5.2）
- **帮助**：关于 Device Studio / 使用说明（点开就是本文档）

# 3. 建工程

**新建设备**（文件 → 新建设备，或设备列表上的「新建设备」）：填设备 ID（小写字母 / 数字 /
下划线，字母开头，直接当目录名）、名称、型号；对话框底部显示「工作目录」，新建的设备就放在
它下面（可以点「选择」改到别处）。确定后得到：

```text
<你选的目录>/<设备id>/
├── device.yaml        # 设备能力定义：状态 / 命令 / 事件（§6）
└── ui/
    ├── manifest.json  # UI 包描述
    └── index.html     # 入口页面（模板已带 deviceApi 用法示例）
```

**打开别人给的设备**：文件 → 打开设备目录，选中设备目录（含 `device.yaml` 的那个）。
设备列表里的「从列表移除」只是从列表拿掉，不会删文件。

点左侧设备卡片即可启动它——Studio 会在本地跑一个模拟设备，中间栏马上能预览。

# 4. 写界面

## 4.1 目录结构

`ui/` 里怎么组织随你（`css/`、`js/`、`assets/`、多页面都行），只有两条硬要求：

- 必须有 `manifest.json`；
- `manifest.json` 里 `entry` 指向的文件必须存在。

## 4.2 manifest.json

```json
{
  "package": "smart_light_ui",
  "version": "1.0.0",
  "device": { "type": "smart_light", "model": "SL001" },
  "protocol": { "version": 1 },
  "entry": "index.html",
  "api_version": 1
}
```

`version` 是 UI 包版本号，改了界面就往上加一位（0.0.2 → 0.0.3），设备端和 App 靠它判断
要不要更新。

## 4.3 三条页面规矩

1. **一律用相对路径**：`img/logo.png`、`fetch('data.json')`……
   App 会给页面一个带鉴权的路径前缀，相对路径自动带过去；写 `/xxx` 这样的绝对路径会 404。
2. **不要自己写 fetch / WebSocket**：App 会自动往 `<head>` 注入 `deviceApi`，页面里直接调用
   即可，不用 import 任何东西。手写请求拿不到鉴权前缀，也不会有断线重连。
3. **设备是唯一数据源**：页面订阅状态、下发命令；不要自己维护一份"我以为的状态"，
   否则断线重连后会和设备对不上。

## 4.4 deviceApi 速查

```javascript
// 下发命令：resolve 为 {status, data, error, request_id}
const resp = await deviceApi.command('light.set_brightness', { value: 80 });

// 订阅全量状态（如果当前已有状态，会立即回调一次）
deviceApi.onState(state => render(state));

// 主动拉取一次：resolve 为 {version, state}
const { state, version } = await deviceApi.getState();

// 订阅设备事件
deviceApi.onEvent('smart_light.state_changed', data => { /* ... */ });

// 订阅状态补丁（设备只推变化的部分；window.deviceState 会自动应用，一般用不到）
deviceApi.onPatch(ops => { /* ... */ });

// 当前状态与版本号，直接读
window.deviceState;
window.deviceStateVersion;
```

命令名、状态字段名、事件名都要和 `device.yaml`（§6）里定义的一致，否则设备会回
**3001**（参数不对）或 **3002**（未知命令）。

## 4.5 最小示例

```html
<!DOCTYPE html>
<html>
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0,
        maximum-scale=1.0, user-scalable=no">
  <title>Smart Light</title>
</head>
<body>
  <button onclick="deviceApi.command('light.set_power', { power: true })">开灯</button>
  <div id="brightness">--</div>
  <script>
    deviceApi.onState(function (state) {
      document.getElementById('brightness').textContent = state.brightness;
    });
  </script>
</body>
</html>
```

## 4.6 预览与热重载

- 编辑器上方可切换 **源码 / 预览 / 拆分**（源码和预览同屏）。
- 「运行 → UI Hot Reload」打开后，**保存文件约 0.3 秒后预览自动刷新**，不用手动重载。
- 预览里点按钮走的是完整协议链路：右边 Inspector 的 State 实时变化，底部 Protocol Console
  能看到每一帧收发。
- 没接真机时预览连的是 Studio 里的模拟设备，行为和真机一致（同一份协议实现）。

# 5. 打包：ui.pkg

设备和 App 实际拿到的是 **ui.pkg**——把 `ui/` 目录打成一个包。

- **何时自动打包**：「运行 → 生成代码」会打包；开着 UI Hot Reload 时保存文件也会重打。
- 产物在设备目录的 `build/ui.pkg`，Studio 会顺手校验（manifest 合法、入口存在、哈希一致）。

## 5.1 .uipkgignore —— 把用不上的文件挡在包外

`ui/` 里常有些文件只有开发时有用：PC 预览脚本、PWA 装桌面用的大图标、设计稿、笔记……
它们不需要进设备，白占固件空间和传输时间。在 **`ui/` 目录里**放一个 `.uipkgignore`
就能把它们排除——**源文件原样保留**，本地预览照样能用：

```text
# 一行一个模式，# 开头是注释

icons/icon-1024.png      # 排除指定文件
serve.py                 # 不含 / 的模式：任意层级的同名文件都排除
*.txt                    # 支持 * 和 ?（* 不跨目录）
design/                  # 结尾 / 表示排除整个目录
```

语法规则：模式相对 `ui/` 目录；含 `/` 的按整条相对路径匹配，不含 `/` 的匹配任意层级的同名
文件；`.uipkgignore` 自己永远不进包。

**怎么判断哪些能忽略**：设备端只会请求 `entry` 页面及它引用的资源。PWA 专用文件
（`manifest.webmanifest`、`sw.js`、`install.html`、超大尺寸的图标）通常都可以排除。
拿不准就先忽略，再用 Studio 预览把所有功能点一遍。

## 5.2 打包时压缩图片

**设置 → 偏好设置… → 打包时压缩图片**（默认开）：打包时把 PNG 量化到 256 色以内，
照片级渲染图通常能省一半以上。**只影响包里的字节，源文件不动**。规则：

- 只压 PNG；压不小就原样放行；
- 带透明像素的图跳过；已经是调色板 PNG 的不再压第二次；
- 色数从 64 起试，画质过关就停（逐像素平均误差很小才算过关），避免渐变起色带。

关掉这个开关，打包时图片就是原样。个别图标还想再小几个 KB 的话，属于进阶操作，
可以另外用 Pillow 之类工具手工重编码（Studio 打包时不会重复压它）。

## 5.3 命令行打包（可选，给脚本 / CI 用）

```bash
device ui build <ui目录> [输出.ui.pkg] [--compress-images]
device ui validate <ui.pkg>
```

# 6. 设备定义（device.yaml）

`device.yaml` 定义设备有什么状态、能执行什么命令、会发什么事件，是界面和设备之间的
**唯一约定**：

```yaml
device:
  id: smart_light
  name: SmartLight
  model: SL001

protocol:
  version: 1

api:
  version: 1

state:                        # 状态字段（类型 + 范围）
  power:
    type: bool
  brightness:
    type: uint8
    min: 0
    max: 100

commands:                     # 命令（页面里 deviceApi.command 的第一个参数）
  - name: light.set_brightness
    params:
      value:
        type: uint8
        min: 0
        max: 100

events:                       # 事件（页面里 deviceApi.onEvent 的事件名）
  - name: smart_light.state_changed
```

支持的类型：`bool` / `uint8` / `uint16` / `int32` / `float` / `string`。
改完 device.yaml 记得「运行 → 生成代码」，设备侧代码才会跟着更新。

# 7. 生成代码、装进设备

**运行 → 生成代码** 会在设备目录产出 `generated/`：

```text
generated/
├── c/
│   ├── device_api.h        你要实现的函数声明（操作真实硬件）
│   ├── device_api.c        参数解析校验后的处理入口（生成，勿改）
│   ├── device_commands.c   命令路由 + 参数校验（生成，勿改）
│   ├── device_state.h      状态结构体
│   └── device_info.h       设备信息
├── manifest.json           UI 包描述（跟着 ui.pkg 走）
├── dart/device_api.dart    Dart 侧强类型封装 —— 可选，设备端用不到
└── simulator/virtual_device.dart
                            Dart 虚拟设备骨架 —— 可选，设备端用不到
```

**装进设备只需要 `c/` 和 `manifest.json`**：`dart/` 是给 Dart 侧（App / PC 工具）把命令
包成有类型的函数调用用的，`simulator/` 是给 PC 上跑虚拟设备用的骨架——设备固件是 C，
这两个目录拷不拷都不影响，移植时可以不管它们。

**你要写的唯一代码**是 `device_api.h` 里声明的函数（真实硬件操作），放进设备 SDK 的
`device_app.c`。命令路由、参数校验（类型错/越界 → 3001，未知命令 → 3002）、状态结构体
都是生成好的。

移植到设备 SDK 的四步：

```text
1. 拷贝 <安装目录>\samples\device_sdk\ 到设备 SDK       (协议运行时)
2. 拷贝 generated/c/* 到设备 SDK 的 app/generated/       (应用层)
3. 实现 device_app.c（device_api.h 里的函数 + 真实硬件驱动）
4. 把 ui.pkg 放进设备文件系统，然后按设备 SDK 的方式编译烧录
```

`samples\` 就在 Studio 安装目录下（绿色版 = `myhome.exe` 旁边），**随安装包一起发给你**：

- **`samples\device_sdk\`** —— 设备端协议运行时的完整源码：`core\`（协议帧 / 分片 / 运行时）、
  `hardware\`（硬件接口约定）、`platform\jieli\`（杰里平台胶水）、`examples\`（应用示例），
  外加 `README.md`（接入说明）和 `deploy_to_sdk` 一键部署脚本。第一步拷的就是它。
- **`samples\light1\`** —— 一个完整示例工程：`device.yaml` + `ui\`（界面源码）+
  `generated\`（生成的代码）+ `device_app.c` / `ui_assets.c`（硬件实现）+ `build\ui.pkg`。
  可以整个拷进设备 SDK 编译（设备上跑的就是它），也可以对着它写自己的设备。

两个都是普通文件夹，直接拷走即可。

一页流程：

```text
① 新建设备 / 打开设备目录     Studio：文件菜单
② 写 device.yaml            状态 / 命令 / 事件
③ 写 ui/                    页面 + manifest.json
④ 预览调试                  Studio：点设备 → 操作 → Inspector / Console / 热重载
⑤ 打包                      Studio 自动打（ui.pkg）；.uipkgignore 排除无用文件
⑥ 生成代码                  运行 → 生成代码 → generated/
⑦ 移植                      按上面四步接进设备 SDK，编译烧录
```

# 8. 常见问题

- **预览是空白**：先确认左侧设备卡片点过启动；再看 Protocol Console 有没有日志。
- **改了文件预览没反应**：确认「运行 → UI Hot Reload」开着；或手动「转到 → 重载 UI 预览」。
- **页面资源 404**：检查是不是写了绝对路径（`/img/...`），改成相对路径（`img/...`）。
- **命令返回 3001**：参数类型或范围不对，对照 device.yaml 里该命令的 params 定义。
- **命令返回 3002**：设备侧没有这条命令——改了 device.yaml 后重新「生成代码」并同步到设备。
- **校验报 Hash mismatch**：包内容和 manifest 声明对不上，重新生成一次即可。
- **包太大**：先加 `.uipkgignore` 排除 PWA / 开发文件（§5.1），再确认「打包时压缩图片」开着（§5.2）。
- **断线了**：右上角「断开」后重新点设备启动；App 侧会自动重连。
